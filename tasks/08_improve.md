# 08 — 개선 반복: 변경 → 확인 → 기록 읽기 → 이유 기록

**상태:** 진행 전

## 목표
가장 약한 소스·언어를 찾아 원인을 고치고, 기준(`eval/thresholds.yaml`)을 넘긴다. 모든 변경은 수치로 증명한다.
원본 프로젝트의 경고: 더 똑똑해 보였던 라우팅 변경이 정확도를 0.93 → 0.84 로 떨어뜨렸고, 평가만이 그것을 보여 주었습니다.

## 파일
- 원인에 따라 다름 (`AGENTS.md` 의 디버깅 지도)
- `eval/golden_qa.jsonl` (질문 추가만. 기존 정답·키 수정 금지)
- `docs/decisions/`

## 완료 조건
- [ ] 오류 표: 틀린 질문 → 실패한 층 (파싱 / 청킹 / 검색 / 라우팅 / 추론) → 수정 → 전후 수치
- [ ] 실험 하나 이상: `chunking` 또는 `retrieval` 설정을 바꾸고 전후 수치를 `docs/decisions/` 에 기록
- [ ] 소스 카드(`not_covers`)를 고쳐 router_accuracy 를 올린 기록 하나 이상
- [ ] 골든 QA 40개 이상, 각 소스 8개 이상
- [ ] `python -m ragbot check` 통과. 다른 소스의 점수를 떨어뜨린 수정은 되돌렸다

## 확인
```
python -m ragbot check
```
